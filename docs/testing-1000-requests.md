## Матрица запросов

Файл: `tests/test_user_requests_1000.py`. Каждый запрос — отдельный тест со стабильным номером и проверкой ожидаемого результата. Генератор проверяет уникальность всех 1000 исходных строк.

| Сценарий | Количество | Что проверяется |
|---|---:|---|
| Поиск в свежем каталоге | 600 | 10 моделей × 3 объёма памяти × 2 цвета × 10 вариантов регистра/пробелов; ожидаемая карточка, клавиатура, отсутствие live fallback |
| Некорректный ввод | 100 | 50 слишком коротких и 50 слишком длинных названий; понятный отказ без обращения к источникам |
| Ничего не найдено | 100 | Сообщение пользователю и отсутствие пустых поисковых сессий |
| Сбой источника/перегрузка | 100 | Недоступность источника, переполненная очередь, неожиданная ошибка; корректный ответ пользователю |
| Выбор категории | 100 | Сохранение запроса, две категории, отсутствие преждевременного поиска товара |

600 положительных случаев включают варианты написания 60 товарных конфигураций, а не 600 независимых товарных моделей. Матрица проверяет реальный `handle_search`, нормализацию, координацию запросов, сессии и построение клавиатуры. Для попаданий используется реальный `CatalogFirstPriceService` с изолированным in-memory каталогом; Telegram-транспорт и внешние источники заменены тестовыми объектами. Сетевые соединения в матрице запрещены.

| Фоновый цикл завершался после ошибки | Искусственная ошибка чтения БД | Следующая итерация выполняется; отмена задачи корректно распространяется |

Дополнительно проверены: ошибка обновления подписки, недоступные/NaN/Infinity/отрицательные цены, сохранение всех символов при разбиении сообщения.

## Параллельные обращения

Три дополнительные проверки используют реальный `SearchRequestCoordinator` и по 1000 вызовов каждая:

1. 1000 разных запросов при ёмкости очереди 1000: все результаты соответствуют запросам, одновременно работают не более 8 загрузчиков, очередь очищается.
2. 1000 разных запросов при ёмкости 200: 200 выполняются, 800 получают `SearchBusyError`, одновременно работают не более 8 загрузчиков.
3. 1000 одинаковых запросов: один вызов загрузчика, результат получают все ожидающие.

Это нагрузочная эмуляция координатора, не 1000 реальных Telegram-клиентов или сетевых обращений к магазинам.

## Повторный запуск

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests
python -m unittest discover -s tests -p test_user_requests_1000.py
python -m unittest discover -s tests -p test_extended_regressions.py
python -m compileall -q app bot.py tests
```

Новые тесты автоматически подхватываются существующим workflow `tests.yml`.

## Ограничения

- Бот не запускался с реальным токеном, уведомления людям не отправлялись; production-данные не изменялись.
- Доступность и актуальная HTML-разметка сайтов магазинов, Telegram API, реальные задержки и лимиты внешних сервисов не проверялись live-запросами.
- Локальный запуск выполнен на Python 3.12; workflow проекта использует Python 3.13, его результат следует проверять отдельно.
- Процент покрытия не измерен: установка дополнительного инструмента потребовала недоступного сетевого разрешения.
- Прохождение тестов не гарантирует отсутствия всех возможных ошибок. Уже объединённые неверные карточки в существующей БД автоматически не разделяются: исправление предотвращает новые ошибочные объединения.
